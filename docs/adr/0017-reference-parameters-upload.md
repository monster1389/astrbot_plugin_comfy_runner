# 文件类参数的值是引用，由插件解析后上传

`image`、`video`、`audio`、`file` 四种参数的值都是一段字符串引用，插件把它解析成字节、
按内容哈希命名上传到 ComfyUI 的 input 目录，再把 ComfyUI 返回的文件名写进目标字段。

引用支持五种写法：`attachment` / `attachment:序号` 取本条消息（其次引用消息）里同类型的附件；
`task:<任务ID>` / `task:<任务ID>:序号`（ADR-0022 新增）引用已有任务的正式产物；
本地绝对路径；`file://` URI；`http(s)` 链接。

不选「插件自动把消息里的图片喂给工作流」的理由：模型没有机会表达意图，用户在群里发张图再随口
问一句，工作流就会自己跑起来。做成显式参数后，模型必须自己写上 `attachment`，语境不对时它可以
反问用户，而不是把不相干的图当参考图用。

也不能只让模型传路径：AstrBot 只把 `File`、`Video`、`Record` 的本地路径写进给模型看的上下文，
`Image` 走的是 `image_urls`，模型看得到图但拿不到路径，所以图片必须有一条从消息链取件的通道。

## 后果

- 上传到 input 根目录而不是子目录：`LoadImage`、`LoadVideo`、`LoadAudio` 的 COMBO 选项只列根目录文件。
- 契约里的 `description` 只写参数语义，取值写法由插件统一补：参数说明末尾，以及漏传必填文件类参数时的报错里。
- 同名内容只落一份（内容哈希），重复使用同一张参考图不会堆文件。
- ComfyUI 没有删除 input 目录文件的接口，上传过的附件会一直留在那边。
- 普通引用解析失败、读取失败、上传失败都发生在同步提交阶段；引用尚在运行的 `task:<任务ID>` 时则先同步校验依赖存在且类型匹配，再转入后台等待上游完成后上传提交。
- 引用接受任意 `http(s)` 链接与任意本地绝对路径，没有目录或主机白名单：模型可以让插件读容器内可读文件、请求内网地址，并把结果落进 ComfyUI 的 input 目录，且文件会整个读进内存、没大小上限。
- 图片本身不经过敏感词过滤，只能靠准入、冷却与并发上限约束。
