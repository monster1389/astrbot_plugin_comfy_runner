# 契约修改在内存中整体刷新

ADR-0013 把对外工具收敛为固定工具、并把工具 Schema 静态化之后，契约不再决定工具注册的形状，只决定工作流工具读到的目录。因此修改契约不必重载整个插件：WebUI 保存或 `/comfy reload` 都先读取全部契约文件、按与启动相同的一套规则整体校验，通过后再就地替换运行中的 `adapter.catalog` 与命令上下文；任何一份文件不合法就整体拒绝，内存里继续使用上一份可用状态。

唯一需要动工具注册的边界是启用契约数量从 `0` 变为 `>0` 或反向跨越：工具本身静态，但没有可用契约时不该注册，恢复后要重新注册。这一同步只发生在边界上，不重载插件、不重启进程，也不中断进行中的后台交付任务，因为这些任务持有的是提交时的契约对象，已经与目录解耦。

## 后果

- 契约文件不合法不再表现为插件加载失败，而是 `/comfy reload` 或 WebUI 保存请求失败，并保持原运行状态。
- `adapter.catalog` 必须就地清空并更新，已绑定的工具闭包才能读到新目录；整体替换字典会让旧闭包继续指向旧契约。
- 后台交付按提交时的契约对象继续完成，热刷新不影响已提交任务的产物收集与发送。
- 工作流与契约文件仍以目录为唯一事实来源（任务状态则由 ADR-0022 引入的 `tasks.db` 独立持久化）。
