# 轮询同一个任务且不盲目重新提交

初版通过 `/prompt` 提交工作流，并以 `/history/{prompt_id}` 轮询同一个任务。提交成功必须同时通过 HTTP 状态、`error`、`node_errors` 与 `prompt_id` 检查；历史出现后先判断执行状态，再读取契约声明的产物。WebSocket 不作为完成判定的必要依赖。

插件不自动重新提交超时或结果未知的任务：已经取得 `prompt_id` 时继续查询该任务；提交结果未知时明确报告执行状态未知，用户主动重试则视为新的执行。

## 后果

- 客户端超时不能直接等同于 ComfyUI 执行失败，任务仍可能在服务端排队或运行。
- 不用隐藏重试制造幂等假象，避免同一请求被重复生成。
- 后续可以用 WebSocket 增强进度展示，但不能形成另一套不一致的完成状态来源。
