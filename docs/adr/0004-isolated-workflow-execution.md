# 每次执行使用独立的工作流副本

每次调用都读取原始工作流 JSON，在独立副本上应用本次参数覆盖，提交后丢弃副本；运行时参数不写回原始文件，也不复用上一次执行的对象。未提供的可选参数保持原始工作流默认值，从而避免连续调用之间发生参数残留。

## 后果

- 原始工作流是默认值的来源，运行时覆盖与持久化修改是两种不同操作。
- 只覆盖本次调用明确提供的参数，未声明或未提供的字段保持原值。
- 调用之间不能通过共享工作流对象传递状态；需要保留的执行信息必须另有明确的记录机制。
- 不遍历或随机改写 `seed` / `noise_seed`；种子只有通过显式参数映射才能覆盖，未提供时保持原值。
- 如果以后需要每次随机，必须在契约中显式声明生成策略，不能恢复隐藏的全局随机化。
