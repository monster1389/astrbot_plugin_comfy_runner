# 契约驱动工具迁移实施计划

把固定文生图实现迁移为契约驱动的独立工作流工具。决策依据为 `docs/adr/0001` 至 `0012`；契约格式见 `schemas/tool-contract-v1.schema.json`，完整示例见 `examples/moss.tool.json`。

本文是迁移期间的操作计划，不记录进度或时间表。迁移完成后删除本文，长期规则留在 ADR、术语表和实际配置 Schema 中。

## 一、迁移范围

第一阶段实现：

- 版本为 `1` 的 `.tool.json` 契约。
- `string`、`integer`、`number`、`boolean` 四类公开输入。
- 图片正式产物的解析、下载与会话交付。
- 启动或重载时的契约校验、动态工具注册和有界并发执行。
- 工作流文件、契约与访问控制所需的管理命令。

契约 Schema 允许声明 `video`、`audio`、`text` 和 `file`，是为了避免文件格式以图片为中心；对应交付尚未实现时，启用此类契约必须明确校验失败，不能按图片处理或静默跳过。

本迁移不做：

- 自动转换旧配置，或同时读取新旧两套配置。
- 工作流映射管理页面。
- WebSocket 完成判定、后台执行或插件内等待队列。
- 提示词结构化、自动 LoRA 选择、专用步数覆盖和全局随机种子。
- 自动修改原始工作流 JSON。

## 二、契约语义

### 2.1 文件与工具身份

- `name.json` 与 `name.tool.json` 配对，前者是原始 ComfyUI API 工作流，后者是工具契约。
- `version` 只能为 `1`。遇到其他版本直接拒绝，不猜测格式。
- `name` 是模型看到的工具名，在全部启用契约中唯一；文件名不是工具名。
- `enabled: false` 只表示不注册，不改变契约与工作流的配对关系。
- `inputs` 可以为空对象，用于没有公开参数的固定工作流；`outputs` 至少声明一个正式产物。

### 2.2 输入参数

每个 `inputs.<参数名>` 定义一个公开参数：

| 字段 | 语义 |
| --- | --- |
| `type` | 公开值的 JSON 类型 |
| `description` | 告诉模型该参数的业务含义，而非节点实现细节 |
| `required` | 是否必须由本次调用提供；省略时为 `false` |
| `target.node` | 工作流中的节点 ID，统一写成字符串 |
| `target.field` | 该节点 `inputs` 中的字面字段名 |
| `enum` | 可选的有限取值集合，元素类型必须与 `type` 一致 |
| `minLength` / `maxLength` | 字符串长度约束 |
| `minimum` / `maximum` | 整数或数值约束 |

契约不为公开参数提供默认值。调用省略可选参数时，目标字段保持原始工作流中的值；不能用上一轮参数、契约中的另一份默认值或随机值代替。

节点 ID 只存在于契约和错误定位中，不进入模型参数 Schema。一个参数只能映射一个字面输入字段；如果该字段是 `[来源节点, 输出槽]` 形式的连线，配置无效，运行时不得自动追踪并改写来源节点。

### 2.3 正式产物

每个 `outputs.<产物名>` 定义一个正式输出映射：

- `type` 声明产物类型。
- `target.node` 指定 `history.outputs` 中的节点 ID。
- `target.field` 指定该节点输出中的字段，如 `images`。

同一目标字段中的全部有效元素都是正式产物，不能只取第一项。任一声明的输出缺失、类型不符或没有有效产物，都按执行结果不完整处理，不能改取其他节点或中间预览。

同一字段内保持 ComfyUI 返回顺序；不同输出映射按产物名排序，保证交付顺序可重复。

### 2.4 给模型生成的参数 Schema

加载契约时，从 `inputs` 生成每个 Function Tool 的独立参数 Schema：

- 根对象为 `type: object`，且 `additionalProperties: false`。
- 每个公开参数转换为对应的 JSON Schema 类型、描述与约束。
- 仅将 `required: true` 的参数名列入根对象的 `required`。
- 不写入参数默认值，不暴露目标节点和字段。

磁盘契约 Schema 与模型参数 Schema 是两层格式；不能用前者直接代替后者。

## 三、Schema 之外的必要校验

JSON Schema 只负责单文件结构。契约加载器还必须执行以下语义校验：

1. `maxLength >= minLength`、`maximum >= minimum`，且 `enum` 中的值满足其他约束。
2. 配对工作流存在且为合法 JSON 对象，启用工具名在整个启用集合中唯一。
3. 每个输入目标节点存在，目标节点含 `inputs` 对象，声明字段存在且不是连线。
4. 每个输出目标节点存在；输出字段是否存在及其实际结构在执行后的 `history` 中继续严格校验。
5. 第一阶段遇到未支持交付类型的启用契约时拒绝加载。

启动校验只依赖本地契约和工作流，不能把 ComfyUI 在线作为插件注册工具的前提。`/object_info` 可用于管理命令的远程辅助检查，但不能替代本地校验，也不能自动决定公开参数或工具语义。

收到工具参数时，再按生成的参数 Schema 校验必填项、未知参数、实际类型和约束；任何错误都在 `/prompt` 之前返回。

## 四、分阶段实施

### 阶段 A：契约加载与注册

实施：

- 在 `requirements.txt` 声明实际使用的 JSON Schema 校验依赖。
- 增加契约模型、单文件 Schema 校验、跨文件语义校验与模型参数 Schema 生成。
- 在插件启动或重载时构建 Function Tool 集合并调用 `context.add_llm_tools()`。
- 增加契约检查命令：能检查包括禁用契约在内的全部文件，并报告文件、参数和节点字段定位。
- 无契约或全部禁用时正常加载；任一启用契约无效时拒绝完成加载。

验收：

- 有效示例注册出名称、描述和参数 Schema 均正确的独立工具。
- 重复工具名、未知字段、错误约束、缺失节点、缺失字段和连线目标均在提交前失败。
- 禁用契约不注册；没有启用契约时管理命令仍可用。

### 阶段 B：通用同步执行

实施：

- 每次调用重新读取原始工作流，在独立对象上只覆盖本次显式提供的参数。
- 删除自动遍历种子、LoRA 堆改写和步数附属文件对执行路径的影响。
- 提交时检查 HTTP 状态、`error`、`node_errors` 与 `prompt_id`；之后只轮询同一任务。
- 根据执行状态和输出映射解析全部正式图片，以标准 URL 参数编码下载。
- 在 AstrBot 入口实现有界并发，超限直接拒绝；插件不增加等待队列。
- 超时或提交结果未知时不自动重新提交。

验收：

- 连续两次调用使用不同参数后，第三次省略参数会恢复原始工作流值。
- 未映射的 `seed` / `noise_seed` 逐值不变；显式种子只修改声明目标。
- HTTP 200 但含提交错误、执行失败、缺少正式输出、下载失败和超时都能被区分。
- 超时路径不会再次调用 `/prompt`，超限调用不会进入插件等待队列。

### 阶段 C：AstrBot 交付与访问控制

实施：

- 从 Function Tool 的实际调用上下文取得当前事件，在入口执行可选访问控制。
- 由 AstrBot 适配层发送全部正式图片，向模型返回简短成功或失败结果。
- 更新工作流与契约管理命令，使其展示文件、配对、启用和校验状态，不再提供全局当前工作流。
- 删除 System Prompt 注入、回复标签提取、自动绘图和历史清理钩子。

验收：

- 模型不需要知道节点 ID、文件路径或 ComfyUI URL，用户能在原会话收到本次全部图片。
- 未支持的产物类型、访问拒绝和并发拒绝都有明确回复，且不会提交工作流。
- 普通聊天不会改变工作流、触发执行或被插入工作流说明。

### 阶段 D：切除旧路径与文档收尾

实施：

- 删除旧固定文生图工具、全局工作流选择状态及专用提示词、LoRA、步数执行代码。
- 保留并改造工作流文件、契约和访问控制管理命令；不保留旧参数兼容层。
- 更新 `_conf_schema.json`，移除不再读取的配置项，只保留服务、访问控制与执行限制等实际配置。
- 更新 `CHANGELOG.md` 中的命令、配置和用户可见行为变化。

验收：

- 所有执行都经由动态工具契约，代码中不存在第二条参数注入或出图路径。
- 原始工作流文件在调用前后逐字节不变。
- 全部测试从插件初始化、命令或 Function Tool 入口进入，只 fake HTTP、消息发送和 LLM provider 等外部边界。

## 五、管理员手动迁移步骤

1. 按 `~/ops/README.md` 的约束备份现有配置和数据。契约仍放在已有工作流数据目录，本迁移不新增需要登记的运行时数据路径。
2. 为每个需要保留的工作流创建同名 `.tool.json`，以 `examples/moss.tool.json` 为格式起点，先设置 `enabled: false`。
3. 为工具填写独立、稳定的名称和面向模型的能力描述，再逐项声明真正需要模型控制的参数。
4. 按下表处理旧配置；旧值只作为人工查找线索，不作为新运行时输入。

| 旧概念 | 手动迁移方式 |
| --- | --- |
| `bindings.input` | 建立提示词参数映射；若旧目标是连线，人工找到应公开的字面来源字段，而不是照旧复制节点 ID |
| `bindings.neg` | 需要模型控制时建立独立字符串参数；固定负面提示词继续留在工作流中 |
| `bindings.output` | 建立正式输出映射，并从实际 `history` 确认字段与产物类型 |
| `.steps.json` | 固定值写回工作流默认值，或建立显式整数参数；新执行器不读取该附属文件 |
| `.lora.json` 与 LoRA 选择 | 默认堆留在工作流中，或把确需公开的控制表达为普通参数；不迁移目录注入和触发词机制 |
| `json_file` / `state.json` | 不再迁移全局选择；每个启用契约独立注册 |
| 自动随机种子 | 找到实际种子来源并建立显式整数映射；省略时保留原值 |

5. 重载插件并运行契约检查命令。修正所有错误后，再将契约设为 `enabled: true` 并再次重载。
6. 逐个工具做一次真实调用，随后验证连续调用无参数残留、相同显式参数可复现、正式产物完整交付。
7. 验证完成前不删除旧配置备份。确认新路径稳定后，再由管理员清理不再读取的旧附属文件和配置值。

## 六、提交与切换验收

每个实施阶段单独提交，提交前必须通过：

```bash
scripts/check.sh
```

最终切换前必须证明：

- Schema 自身通过 Draft 2020-12 检查，示例通过校验，非法契约不能注册。
- 有效契约能注册多个互不干扰的工具，空启用集合能正常加载。
- 提交错误、执行错误、输出错误、网络错误、超时和并发拒绝不会互相混淆。
- 连续调用无参数残留，未声明字段与种子不被修改，原工作流文件不被写回。
- 多图片全部交付，未声明节点和中间预览不会被取用。
- 自动绘图与对话注入已移除，旧配置不会被双读。

真实环境切换使用 AstrBot 插件重载；需要进程级重启时执行 `docker restart astrbot`。回退代码或恢复配置按 `~/ops/README.md` 操作，插件不另造恢复机制。
